## 需求概述

美工版、运营版在现有 LinkFox 商品套图 V4 生图链路中接入敏感词规避与预设词语替换。词库及词条由 LinkFox 维护，我方提供选择、任务保存和生图传参能力。以下六个重点与功能需求第 1～6 节一一对应。

| 核心重点 | 本期规则 |
|---|---|
| 1. 各入口的选择与应用 | 两端均覆盖新增、编辑、查看、批量导入、批量修改。两类词库独立选填、各单选；导入统一应用到实际创建的任务；批量修改分别保持／设置／清空，默认及区域隐藏提交时均保持不变。 |
| 2. 词库查询与任务存储 | 任务只存两个 ID，名称实时查询；不持久化词库列表。素材查询接口按 `type=11/12` 区分类别，每页 100 条，系统自动取齐后展示；按实际代理响应解析，ID 全程保持精度。 |
| 3. 现有 V4 接口新增传参 | 在现有请求顶层增加 `sensitiveLibraryId`、`replaceLibraryId`，分别使用任务保存的 ID；两项独立、各单值，未选择则省略对应字段。 |
| 4. 词库回显与异常处理 | 正常查询及自动取页显示加载中，失败或异常未取齐显示加载失败，完整查询成功后未找到 ID 才提示“词库当前不可选”；均保留 ID，编辑可更换、清空，查看只读，不自动修复。 |
| 5. 未启用 LinkFox 时的处理 | 整组跟随现有 LinkFox 子模型一起隐藏，保留配置，再显示时恢复；其他模型请求不传这两个字段。 |
| 6. 提交与失败后复制重跑 | 不新增提交前词库可用性拦截，直接按已存 ID 调用。失败沿用现有流程；复制重跑创建新任务并继承两个 ID，用户可更换或清空；原样重提仍可能失败。 |

## 原型使用说明

原型使用静态数据，不调用真实接口；实际业务按下文功能需求执行。

- 演示切换：顶部切换五个场景，左侧模拟启用模型及词库查询状态；样例包含长名称和同类重名。
- 默认状态：新增／导入两项未选，批量修改两项保持不变；编辑／查看默认演示两个原 ID 均不在列表，可切换为正常列表。异常默认值仅用于演示，实际按实时查询结果回显。
- 保存与恢复：模拟保存后，编辑／查看使用保存的 ID。“恢复初始演示”保持当前页签，恢复仅 LinkFox 和各场景初始状态。
- 提交反馈：“保存并提交生图”仅在预览下方展示模拟反馈及两个 ID／未选择状态。

演示控件、样例、计数、结果及蓝色虚线均为评审辅助，不进入业务页面；查看场景的外部演示控件不代表任务可编辑。

## 功能需求

### 1. 各入口的选择与应用

美工版、运营版均覆盖以下五个入口。两类词库独立选填、各单选，不自动选中通用词库或唯一候选项；沿用各入口既有任务操作权限及可编辑状态。

| 入口 | 默认值与操作 | 应用范围 |
|---|---|---|
| 新建任务抽屉 | 普通新增两项未选；复制重跑按第 6 节继承 ID。可选择、更换、清空 | 当前新建任务 |
| 编辑任务抽屉 | 按已保存 ID 回显，可更换、清空 | 当前可编辑任务 |
| 查看任务抽屉 | 按已保存 ID 只读回显，查询重试按第 4 节 | 当前被查看任务 |
| 批量导入弹窗 | 两项未选，在弹窗统一选择，可更换、清空 | 本次实际创建的所有任务，含待完善任务 |
| 批量修改弹窗 | 两项分别默认“保持不变” | 本次选中且允许修改的任务 |

批量导入：

以提交导入时的最终选择，将相同的两个 ID 写入每个实际创建的任务；未选类型为空，不读取其他任务或上次导入的配置。待完善任务保留配置并可后续编辑；先选后隐藏仍保存本次 ID。既有导入校验、范围、数量限制、状态及逐行处理不变，失败且未创建的行不生成配置记录。

批量修改：

| 操作 | 选择要求 | 保存结果 |
|---|---|---|
| 保持不变 | 不选择 | 各任务保留自己的原 ID，不以某个任务的配置覆盖其他任务 |
| 设置词库 | 展示单选框，必须选择本类型一个候选项 | 各任务该类 ID 更新为本次选择 |
| 清空 | 不选择 | 各任务该类 ID 置空 |

- 两项操作独立；只修改其他任务字段时均保持原值。“保持不变”和“清空”均保留字段灰色说明；“清空”另展示对应操作结果提醒。
- 区域显示且“设置词库”未选具体 ID 时，提示选择并阻止本次批量修改；清除临时选项仍属未选完，不等于“清空”。这是表单完整性校验，不是生图前可用性校验。
- 区域隐藏时两项均按“保持不变”提交，不执行隐藏的设置／清空或必选校验；再显示恢复本次操作及临时选择，设置仍需选具体 ID。前后端均须按此处理，不能只隐藏控件而仍提交修改。
- 沿用既有可编辑状态、操作权限及修改结果反馈。

### 2. 词库查询与任务存储

任务仅新增以下两个可空字段；保存、导入和批量修改均只提交 ID，不保存名称、词条版本或列表快照。

| 任务字段 | 对应词库及查询类型 | 我方前后端接口传值 |
|---|---|---|
| `sensitiveLibraryId` | 敏感词库，`type="11"` | 完整字符串或 `null` |
| `replaceLibraryId` | 替换词库，`type="12"` | 完整字符串或 `null` |

- 任务未配置或明确清空时，字段值为 `null`；批量修改“保持不变”时保留原值，按第 1 节执行。
- ID 超出 JavaScript 安全整数范围，前端不得转为 `Number`；后端可用字符串或精确的 64 位整数存储，全程不经浮点转换。调用 LinkFox 时按其 `Long` 要求精确序列化，传参规则见第 3 节。
- 设置／更换只更新对应 ID，清空只将对应 ID 置为 `null`，另一类不变；空值不用 `0`、空字符串、空数组或字符串 `"null"`。历史任务缺字段按未选处理，不回刷、补选；仅编辑其他字段时保留原配置，旧调用方未传时保持原生图行为。
- 名称仅按“类型 + ID”匹配本次查询结果，不记录、比较或兜底使用历史名称。不建立词库同步表、定时任务、跨会话持久化缓存。

查询接口与解析：

沿用当前账号、业务端及 LinkFox 授权／调用通道，凭证由服务端管理，不跨上下文串用列表。调用 `POST /linkfox-ai/image/v2/material/list`，`type` 为字符串，`pageNum`、`pageSize` 为数字；替换词库将示例的 `"11"` 改为 `"12"`。

接口文档：https://wiki.linkfox.com/docs/linkfox-ai/materials

```json
{
  "type": "11",
  "pageNum": 1,
  "pageSize": 100
}
```

已核对的代理通道按以下层级解析，不能直接套用官方示例的 `data.list`：

| 内容 | 路径与类型 |
|---|---|
| 业务成功条件 | 根层 `code` 为字符串 `"0"`，且 `data.code` 为数字 `200` |
| 词库列表 | `data.data.list`，数组；每项 `.id`、`.name` 均为字符串 |
| 总数 | `data.data.total`，数字 |
| 是否还有下一页 | `data.data.hasMore`，实测及示例为布尔值；文档标为 number，接入时核对实际通道 |

HTTP 成功不等于业务成功，两层状态及结构均须有效。有效空数组与查询失败区分；列表缺失、`null`、类型错误均按第 4 节加载失败处理。

查询时机与自动分页：

1. 每次打开入口，区域显示时分别查询两类词库；初始隐藏则等本次首次显示再查询。两类独立加载，一类失败不影响另一类、用户选择或其他表单内容；查询中或失败后不能选择尚未取得的候选项。
2. 每类从第 1 页开始，每页固定 100 条；`hasMore=true` 时依次请求下一页，直至 `false`。不因单页不足 100 条或单凭 `total` 提前结束；每类取齐后按接口顺序展示，两类无需互相等待。
3. `total` 辅助核对完整性，例如 `hasMore=false` 但累计结果少于总数，按第 4 节加载失败状态处理。任一页网络失败、超时、业务失败或结构异常同样处理；不展示部分候选项、不据此判定原 ID 缺失。重试从失败类型的第 1 页重新取齐，保留另一类结果和表单。
4. 同次打开复用结果，展开／滚动下拉框、选择、隐藏后再显示或批量任务行数增加均不重复查询。关闭即丢弃结果，再次打开且显示时刷新；隐藏期间不发起查询。隐藏后返回的请求可供本次复用，但不重新显示区域或改写 ID；关闭后的旧请求不得覆盖再次打开的新上下文。

### 3. 现有 V4 接口新增传参

现有生图链路已使用 `POST /linkfox-ai/image/v4/make/productMarketMaterial`，本期在其 JSON 顶层增加以下字段：

接口文档：https://wiki.linkfox.com/docs/linkfox-ai/product-suite-v4

| LinkFox 入参 | 来源 | 类型与传参规则 |
|---|---|---|
| `sensitiveLibraryId` | 任务保存的敏感词库 ID，查询类型 `11` | 可选单值 `Long`，精确序列化；为空省略 |
| `replaceLibraryId` | 任务保存的替换词库 ID，查询类型 `12` | 可选单值 `Long`，精确序列化；为空省略 |

两个参数可都不传、仅传一个或同时各传一个，不传名称、数组或逗号拼接 ID。用户更换／清空并保存后，出站使用新配置。联调时核对实际出站请求，确保 ID 按 `Long` 要求传递且不丢精度。

按官方文档，敏感词库命中后由 AI 改写规避；替换词库按预设映射替换。两者同时使用时先改写、再替换，替换不以敏感词命中或改写成功为前提。不存在、无权访问或类型不匹配的 ID 返回参数校验错误，按第 6 节处理。上述词库效果及错误返回尚未实测，接口受理成功不等于最终效果验收。

### 4. 词库回显与异常处理

区域显示时，按对应类型的完整查询结果回显；只有完整列表查询成功，才能判断原 ID 是否在列表中。

| ID 与查询状态 | 字段展示与操作 |
|---|---|
| 无 ID | 查看始终显示“未选择”，不显示加载、错误或重试；可配置入口显示对应占位、加载中、暂无可选词库或加载失败状态，失败可重试，不自动选择。 |
| 有 ID，正在查询／自动取页 | “正在加载词库名称”及完整 ID，暂不可选择候选项。 |
| 有 ID，完整列表成功且找到 ID | 展示本次返回的名称。 |
| 有 ID，完整列表成功但未找到 ID，含有效空列表 | “词库当前不可选”及完整 ID；可配置入口提示“原词库当前不可选，请重新选择或清空。”，查看提示“当前列表中未找到该 ID。”。不据此断言已删除。 |
| 有 ID，请求失败或分页异常导致未取完整 | “词库加载失败”及完整 ID，提示“词库加载失败，请重试。”并提供重试；不能判为当前不可选。 |

查询、回显和重试均不修改 ID 或触发生图，不自动清空、不用同名项替换。只有用户明确更换／清空并保存才改变配置；保存与提交不受上述查询状态拦截，按第 6 节处理。

### 5. 未启用 LinkFox 时的处理

整组复用各入口现有“LinkFox 子模型”的显示条件：仅 LinkFox 或包含 LinkFox 的混合模型显示；未启用 LinkFox 时一起隐藏。批量混选直接沿用既有条件。

- 隐藏包括标题、说明、字段及提示，不留空白占位或禁用控件；查看即使保存历史 ID 也遵循此规则。查询时机按第 2 节执行。
- 隐藏不清空已保存 ID 或本次选择，再显示恢复。新增、编辑及导入保存不能因字段未渲染而写成空值；批量修改的隐藏操作按第 1 节处理。
- 未启用 LinkFox 时不调用 LinkFox；其他模型请求始终不带这两个字段，任务可保留 ID，其他模型的映射及生成规则不变。

### 6. 提交与失败后复制重跑

| 操作 | 处理规则 |
|---|---|
| 保存为待提交 | 沿用既有保存校验，不触发生图；允许保留当前不可选的 ID。 |
| 保存并提交、列表直接提交、批量提交 | 沿用现有提交确认弹窗及额度等校验；不额外或逐任务查询列表，不新增词库可用性拦截；直接按第 3 节传已存 ID，由 LinkFox 校验。 |

加载中、加载失败、分页未完整、有效空列表、完整列表缺少原 ID 均按上表处理。“选填”不代表可省略已有 ID；调用失败也不得自动删 ID 或移除词库参数重试。批量修改“设置但未选”的校验按第 1 节执行。

1. 单模型全部失败进入“已完成”，原任务不恢复编辑；多模型沿用各模型结果及整体状态判定，不因 LinkFox 失败将其他模型一并判失败。
2. 仅明确识别为词库参数错误时，在既有失败原因处补充：“词库不可用，请复制重跑后，在新任务中更换或清空对应词库，再重新提交。”保留实际错误信息；其他错误沿用原原因，不凭列表缺失或任意接口错误推断词库问题，具体错误码／内容待联调。
3. “已完成”的现有“复制重跑”在“建任务”创建新任务，逐项继承来源的完整两个 ID；空值或历史缺字段仍为空。不查询名称、不复制列表，不因 ID 当前不可选、查询失败或未启用 LinkFox 丢弃配置。
4. 复制不自动提交或修复 ID。打开新任务按第 2、4、5 节查询、显隐和回显；更换／清空后保存提交只影响新任务，原样重提可能再次失败。
5. 两端均适用；已有批量复制如共用此流程，按各来源任务独立继承，不串用 ID。其他复制信息、权限及状态沿用既有流程。

## 验收标准

以下 20 项均需覆盖美工版、运营版的适用场景。四个可配置入口验证只存 ID 及后续出站请求，查看验证只读回显，复制重跑验证独立继承。涉及查询、保存及出站传参的项目，需核对实际接口报文和任务保存结果；文案及细则以对应章节为准。

| 编号 | 验收场景 | 预期结果 |
|---:|---|---|
